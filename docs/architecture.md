# Устройство

```
src/DstFarm.Core    логика без интерфейса
src/DstFarm.Cli     команды и полноэкранный экран на Spectre.Console
tests               xunit-тесты на генерацию конфигов и профиль фарма
```

.NET 10, C# 14, `TreatWarningsAsErrors`. Релиз собирается в один self-contained `dstfarm.exe`
под win-x64 — на целевой машине .NET не нужен.

## Core

**`FarmConfig`** — все настройки и производные пути. Сериализуется в `config.json` рядом
с exe. Здесь же `HasClusterToken()`: токен считается валидным, если файл существует и в нём
больше 20 символов.

**`ClusterWriter`** — генерация каталога кластера. Собирает `cluster.ini`, по одному
`server.ini` и `worldgenoverride.lua` на шард, пустой `modoverrides.lua`. Пользовательские
файлы не перетираются без `overwrite: true`, а `modoverrides.lua` не трогается никогда —
туда люди кладут свои моды. Профиль фарма живёт в `BuildWorldGen`.

**`SteamCmdInstaller`** — качает `steamcmd.zip`, распаковывает, гоняет
`+login anonymous +app_update 343050`. Код возврата 7 после самообновления steamcmd
считается успехом наравне с 0.

**`LogTail`** — следит за дописываемым файлом. Понадобился потому, что stdout сервера
уходит в pipe и буферизуется блоками: панель замирала, хотя сервер работал. Собственный
лог DST пишет сразу, его и читаем; если файл не появился за 20 секунд, откатываемся
на stdout, чтобы панель не молчала совсем.

**`ServerSupervisor`** — держит шарды живыми. Каждый шард это `ShardRunner`: процесс сервера
с перехваченными stdout/stderr (пишутся и в файл, и в событие `Log`) и открытым stdin, через
который уходит `c_shutdown(true)` при остановке. Цикл раз в две секунды проверяет процессы,
поднимает упавшие через `RestartDelaySeconds`, смотрит стоп-флаг и время планового рестарта.
Убийство процесса — только если за 45 секунд сервер не завершился сам.

**`SupervisorControl`** — управление супервизором, работающим в другом процессе:
pid-файл, стоп-флаг, запуск себя же с аргументом `supervise`.

**`UptimeTracker`** — копит суммарный аптайм в `.runtime/state/uptime.json`.

## Cli

**`Program`** — разбор аргументов и команды. Без аргументов открывается полноэкранный режим;
если ввод или вывод перенаправлены, вместо него печатается статус.

**`Dashboard`** — экран на `AnsiConsole.Live` в альтернативном буфере терминала.
Настройки — список `SettingItem` (флаг, выбор из списка, число, текст), каждый знает,
как себя показать и что делать по стрелкам. Изменения помечают кластер «грязным», пока их
не применят клавишей `G`.

Супервизор запускается прямо в процессе интерфейса отдельной задачей, поэтому его лог виден
живьём в нижней панели. Для автозапуска без окна есть `start --detach` — там супервизор
поднимается отдельным процессом.

## Границы

Инструмент не трогает клиент игры: не запускает его, не эмулирует ввод, не влияет на выдачу
дропов. Всё, что он делает — ставит сервер, пишет конфиги и следит, чтобы процесс жил.
